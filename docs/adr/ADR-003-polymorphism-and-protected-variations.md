# ADR-003: Поліморфні політики тарифів та ізоляція змін

## Статус
Прийнято (Accepted)

## Принципи GRASP
Polymorphism, Protected Variations

## Контекст
Розрахунок застави й сервісного збору в `LegacyLibraryProcessor` — каскад `if / else if` за текстовим полем категорії. Нова категорія або зміна відсотків вимагає правки того самого методу (порушення OCP). Невідома категорія не дає помилки (див. ADR-001, проблеми 4–5).

## Рішення
1. **Protected Variations.** Змінну частину (формулу тарифу) закрито стабільним контрактом `LoanFeePolicy` з **одним** методом `LoanFee feeFor(BigDecimal bookValue)`; застава й збір рахуються разом і повертаються незмінним record `LoanFee`.
2. **Polymorphism.** Окремий клас на кожну категорію: `StandardLoanPolicy`, `AcademicLoanPolicy`, `RareLoanPolicy`. Каскаду умов немає.
3. **Вибір політики.** Кожна константа `BookCategory` несе свою політику з реєстру `LoanPolicies`. Зовні політика не видна: `Book` викликає `category.feeFor(value)` (Закон Деметри).
4. **Інші точки нестабільності** теж закрито контрактами: сховище читачів (`ReaderRepository`), каталог (`BookCatalog`), канали сповіщення (`LoanIssuedListener`), джерело введення (`LineReader`).
## Альтернативи (QOC)

| Question | Option | OCP / Protected Variations | Безпека типів | Простота |
|---|---|:---:|:---:|:---:|
| Як обирати тариф за категорією? | A. `if / else if` за рядком (як було) | − | − | + |
| | B. `switch` за enum у сервісі | − | + | + |
| | C. `Map<String, LoanFeePolicy>` + статична фабрика за рядком | + | − (помилка лише в рантаймі, дубль валідації) | 0 |
| | **D. Політика в константі enum `BookCategory` + реєстр `LoanPolicies`** | **+** | **+ (нова категорія без політики не скомпілюється)** | 0 |
| Скільки методів у контракті? | A. `calculateDeposit` + `calculateServiceFee` | 0 | 0 | 0 |
| | **B. Один `feeFor` → `LoanFee`** | **+** | **+** | **+** |

Conclusion: обрано **D** і **B**. Варіант C відхилено: він дублював розбір категорії у фабриці й в enum та перетворював помилку «немає політики» на помилку часу виконання. Контракт з одним методом дає LCOM4 = 1 для кожної політики без штучних припущень.

## Наслідки
* (+) Нова категорія = новий клас політики + рядок у `LoanPolicies` + константа в `BookCategory`; код розрахунку й сервіси не змінюються.
* (+) Невідома категорія дає `IllegalArgumentException` з переліком допустимих значень.
* (+) Розрахунок у `BigDecimal` із округленням `HALF_UP` до копійок; збіг із формулами легасі перевіряє `LibraryChecks.feesMatchLegacyFormula`.
* (−) Три майже однакові класи політик; допустиме заради явного поліморфізму, вимаганого завданням.
